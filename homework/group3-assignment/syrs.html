PART 01

系统需求规格书 SyRS（表 5.1）

1.概述

1.1 系统目的

线控底盘平台作为高级别自动驾驶整车的执行层，接收自动驾驶大脑下发的规划轨迹与运动指令，无机械连接地完成转向、制动、驱动与悬架控制，把驾驶意图毫秒级、安全、平顺地翻译为车轮运动；在单点故障情况下仍能进入可控的最小风险状态，支撑 Robotaxi 城市载客、高速干线物流、无人配送与自动泊车等场景的商业落地。

1.2 系统范围

  • 纳入范围：线控转向（SbW）、线控制动（BBW）、线控驱动（DbW）、主动悬架、底盘域控制器、冗余安全系统的系统级需求；外部接口、运行模式、性能、环境与安全需求。
  • 排除范围：环境感知、决策与轨迹规划算法（上游智驾系统）；车身结构与内外饰；动力电池本体研发；充电桩与补能网络。
  • 外部实体：自动驾驶大脑（规控系统）、高精定位与 V2X、整车厂 OEM、车队运营商、远程安全员、底盘零部件供应商、监管/认证机构、售后维保体系。

1.3 系统概述

平台在整车体系中处于「决策」与「车轮」之间：上游接入规划轨迹、定位与车路协同信息；中游由底盘域控制器统一解算并协调四大执行系统与冗余安全单元；下游面向整车集成、车队运营与售后维保。六层结构见 作业 1 系统树，业务与相关方诉求见 作业 2 StRS。

2.功能需求（Functional Requirements）

下表把作业 2 的相关方需求（SR-xx）分解为系统应执行的功能，编号 FR-xx，作为后续架构设计与测试验证的输入。

编号功能功能描述溯源相关方需求
FR-01指令接收与解析通过车载网络接收上游规划轨迹、目标车速/横摆/转角/扭矩/制动力指令及驾驶模式，并完成校验、解析与时序对齐。SR-01 智驾开发商
FR-02运动解算基于车辆动力学模型与车辆状态，解算各执行器目标转角、驱动扭矩、制动压力与悬架阻尼/车高。SR-01 / SR-09
FR-03线控转向控制控制前/后轴转向电机跟踪目标转角，支持可变传动比与后轮转向，并提供路感反馈模拟。SR-01 / SR-04
FR-04线控制动控制EHB 常规制动与 EMB 四轮独立制动协调动作，并与驱动侧完成制动能量回收协同。SR-01 / SR-03
FR-05线控驱动控制前后轴电机扭矩分配与扭矩矢量控制，执行牵引力控制，并受 BMS 与高压状态约束。SR-01 / SR-06
FR-06主动悬架控制根据工况与预瞄路面调节空气弹簧刚度/车高与 CDC 阻尼，兼顾舒适与操控，并为感知传感器提供稳定基座。SR-04
FR-07稳定性控制运行 VDC / ESP 等横摆与侧滑控制，在低附着、极限工况下维持车辆稳定。SR-04 / SR-07
FR-08状态监控与故障诊断实时监测传感器、执行器、电源、通信与计算链路状态，定位故障并分级。SR-03 / SR-05 / SR-08
FR-09失效降级与 MRC按故障等级触发冗余切换、限速降级或最小风险策略（MRC）：自主靠边减速停车并告警。SR-03 / SR-05 / SR-07
FR-10诊断与数据记录生成故障码，记录运行与故障日志、标定参数，支持回读与远程上报。SR-08 / SR-03
FR-11OTA 升级与回滚支持软件与标定参数远程下载、校验、刷写，失败或校验不通过时回滚至上一安全版本。SR-09
FR-12上电与出车自检上电及出车前完成各子系统自检与状态确认，自检不通过不得进入正常运行模式。SR-07 / SR-08

3.易用性需求（Usability Requirements）

  • 乘坐品质：加减速与转向平顺，纵向加速度变化率（jerk）与侧向加速度受限，保证乘客舒适（对应 SR-04）。
  • 可诊断性：维保人员可通过标准诊断接口快速读取系统状态与故障定位，关键部件可更换（对应 SR-08）。
  • 可监控性：运营端与远程安全员可直观获取车辆状态、故障等级与告警信息，状态含义明确、无歧义。

4.性能需求（Performance Requirements）

编号性能项指标要求验证方式
PR-01端到端控制延迟自上游指令接收到执行器输出响应，端到端延迟 ≤ 20 ms。台架闭环 + 时延测量
PR-02转角跟踪精度前轮目标转角跟踪误差 ≤ ±0.1°；后轮转角按控制策略精确跟随。转向台架 + 实车轨迹测试
PR-03执行器响应时间扭矩 / 制动压力级执行器响应 ≤ 10 ms；域控闭环周期 5–10 ms。台架阶跃响应测试
PR-04冗余切换时间主链路失效后冗余单元接管 ≤ 50 ms，期间不丧失基本转向/制动能力。故障注入测试
PR-05乘坐品质纵向加速度、侧向加速度及其变化率满足标定阈值，兼顾舒适与操控。乘坐品质试验 + 体感标定评审
PR-06运行可用率运营期间关键故障可被及时识别与上报，可用率满足车队运营目标。运营数据统计 + 日志审查
PR-07适配范围平台可适配至少两类整车（乘用车 / 商用车），安装接口与标定参数可配置。车型适配评审 + 环境试验

6.系统运行（System Operations）

  • SP-01 指令接收：接收上游轨迹、目标运动指令与车辆状态反馈，完成校验与时序对齐。
  • SP-02 决策解算：域控基于动力学模型解算各执行器目标量，运行稳定性控制策略。
  • SP-03 协同执行：协调转向、制动、驱动、悬架执行，并进行稳定性与平顺性优化。
  • SP-04 状态监控：实时监测各链路状态，进行故障诊断与分级。
  • SP-05 降级与告警：按故障等级触发冗余切换、降级或 MRC，并向运营端上报。

7.系统模式与状态（Modes and States）

运行模式触发条件系统行为
自检模式上电 / 出车前各子系统自检与状态确认；不通过则锁定，不进入正常模式。
正常模式自检通过、各链路无故障全功能闭环执行，跟踪规划轨迹。
降级模式非关键故障或冗余切换限制车速/功能范围，维持可控行驶并上报。
最小风险策略 MRC关键链路失效、无法继续安全行驶自主靠边减速停车，开启警示，等待远程介入。
驻车模式到达目的地、泊车完成或运营结束施加驻车制动，关闭动态执行，进入低功耗待命。

8.物理特性（Physical Characteristics）

  • 执行器与域控需满足整车布置空间、安装接口与整备质量约束；平台化部件在多车型间复用。
  • 关键部件（双绕组电机、双回路制动、冗余电源）的重量、体积与功耗需在整车成本目标内权衡。
  • 高压部件需满足电气间隙、爬电距离与绝缘隔离要求。

9.环境条件（Environmental Conditions）

  • 工作温度、振动、冲击、防护等级满足车规级环境条件；
  • 适应晴雨、冰雪、低附着路面与高低温等运行环境；低温下驱动扭矩输出按电池与电机特性受限；
  • 供电电压波动、电磁兼容满足车载电气环境要求。

10.信息安全需求（System Security）

  • 控制指令与诊断通信具备身份鉴别、完整性校验与防篡改能力；
  • 诊断接口与 OTA 通道需访问控制与安全刷写，防止未授权写入；
  • 运行数据、故障日志按数据安全要求存储与传输，支持敏感信息清除。

11.信息管理需求（Information Management）

  • 统一管理运行数据、故障日志、标定参数与软件/标定版本，保证可追溯、可回滚；
  • 需求、接口、标定与版本变更走配置管理流程，留痕并可关联到对应车辆；
  • 日志时间戳与车辆配置一一对应，支持事后复盘与责任界定。

12.政策法规需求（Policy and Regulation）

  • 满足道路车辆准入、功能安全（ISO 26262）与预期功能安全（ISO 21448 / SOTIF）相关要求；
  • 满足自动驾驶数据安全、上路试点与远程监管相关法规；
  • 需求、设计与测试证据可追溯，支持认证审核。

13.生存周期保障需求（Life Cycle Sustainment）

  • 运营期提供远程监控、在线诊断、保养提醒、备件供应与现场维修支持；
  • 软件缺陷与标定优化通过 OTA 修复，支持版本回滚；
  • 关键部件可更换、备件尽量通用；车辆退役时完成高压部件拆解回收与车载数据清除。

14.项目约束（Project Constraints）

  • 成本：平台与冗余配置控制在整车成本目标内；
  • 进度：需求基线、车型适配、测试认证与投放节点按项目计划锁定；
  • 资源：研发算力、台架、测试场地与供应链产能构成约束条件。

15.假设与依赖（Assumptions and Dependencies）

  • 假设上游智驾系统按约定接口输出轨迹与运动指令，并保证指令在有效范围内；
  • 依赖 BMS 提供电池状态与扭矩约束、定位单元提供位置信息、云端提供 OTA 与监控后台；
  • 平台性能指标受整车动力、电池容量与传感器配置约束。
