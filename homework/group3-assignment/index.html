PART 01

系统需求规格书 SyRS（表 5.1）

1.概述

1.1 系统目的

线控底盘平台作为高级别自动驾驶整车的执行层，接收智驾大脑的规划轨迹与运动指令，无机械连接地完成转向、制动、驱动与悬架控制，把驾驶意图毫秒级、安全、平顺地翻译为车轮运动；单点故障下仍能进入可控的最小风险状态，支撑城市载客、干线物流、无人配送与自动泊车等场景落地。

1.2 系统范围

  • 纳入：SbW、BBW、DbW、主动悬架、底盘域控制器、冗余安全系统的系统级需求，及外部接口、运行模式、性能、环境与安全需求。
  • 排除：环境感知、决策与轨迹规划算法（上游智驾系统）；车身结构与内外饰；动力电池本体研发。
  • 外部实体：智驾大脑、高精定位与 V2X、OEM、车队运营商、远程安全员、零部件供应商、监管认证机构、售后维保。

1.3 系统概述

平台处于「决策」与「车轮」之间：上游接入轨迹、定位与车路协同信息；中游由域控统一解算并协调四大执行系统与冗余单元；下游面向整车集成、运营与维保。六层结构见 作业 1 系统树，相关方诉求见 作业 2 StRS。

2.功能需求（Functional Requirements）

将作业 2 相关方需求（SR-xx）分解为系统功能，编号 FR-xx。

编号功能功能描述溯源相关方需求
FR-01指令接收与解析接收上游轨迹、目标车速/横摆/转角/扭矩/制动力指令及驾驶模式，完成校验、解析与时序对齐。SR-01
FR-02运动解算基于动力学模型与车辆状态，解算各执行器目标转角、驱动扭矩、制动压力与悬架阻尼/车高。SR-01 / SR-09

FR-04线控制动控制EHB 常规制动与 EMB 四轮独立制动协调动作，并与驱动侧完成能量回收协同。SR-01 / SR-03

FR-08状态监控与诊断实时监测传感器、执行器、电源、通信与计算链路状态，定位故障并分级。SR-03 / SR-05 / SR-08

FR-12上电与出车自检上电及出车前完成各子系统自检与状态确认，自检不通过不得进入正常模式。SR-07 / SR-08

3.易用性需求（Usability）

  • 乘坐品质：加减速与转向平顺，纵向加速度变化率与侧向加速度受限，保证乘客舒适。
  • 可诊断性：维保人员可通过标准诊断接口快速读取状态与故障定位，关键部件可更换。
  • 可监控性：运营端与远程安全员可直观获取车辆状态、故障等级与告警，含义明确无歧义。

4.性能需求（Performance）

编号性能项指标要求验证方式
PR-01端到端控制延迟指令接收到执行器输出响应，端到端延迟 ≤ 20 ms。台架闭环 + 时延测量
PR-02转角跟踪精度前轮目标转角跟踪误差 ≤ ±0.1°；后轮转角按策略精确跟随。转向台架 + 实车测试
PR-03执行器响应时间扭矩 / 制动压力级响应 ≤ 10 ms；域控闭环周期 5–10 ms。台架阶跃响应测试
PR-04冗余切换时间主链路失效后冗余接管 ≤ 50 ms，期间不丧失基本转向/制动能力。故障注入测试
PR-05乘坐品质纵向/侧向加速度及其变化率满足标定阈值，兼顾舒适与操控。乘坐品质试验 + 标定评审
PR-06运行可用率关键故障可及时识别与上报，可用率满足车队运营目标。运营数据统计 + 日志审查
PR-07适配范围可适配至少两类整车（乘用车 / 商用车），安装接口与标定参数可配置。车型适配评审 + 环境试验

接口对接实体接口内容与信号介质 / 协议

6.系统运行（Operations）

  • SP-01 指令接收：接收轨迹、目标指令与车辆状态反馈，完成校验与时序对齐。
  • SP-02 决策解算：域控基于动力学模型解算各执行器目标量，运行稳定性策略。
  • SP-03 协同执行：协调转向、制动、驱动、悬架执行，优化稳定性与平顺性。
  • SP-04 状态监控：实时监测各链路状态，进行故障诊断与分级。
  • SP-05 降级与告警：按故障等级触发冗余切换、降级或 MRC，并向运营端上报。

7.系统模式与状态（Modes）

运行模式触发条件系统行为
自检模式上电 / 出车前各子系统自检与状态确认；不通过则锁定，不进入正常模式。
正常模式自检通过、各链路无故障全功能闭环执行，跟踪规划轨迹。
降级模式非关键故障或冗余切换限制车速/功能范围，维持可控行驶并上报。
最小风险 MRC关键链路失效、无法继续安全行驶自主靠边减速停车，开启警示，等待远程介入。
驻车模式到达目的地、泊车完成或运营结束施加驻车制动，关闭动态执行，进入低功耗待命。

8.物理特性与环境条件

  • 执行器与域控满足整车布置空间、安装接口与整备质量约束，平台化部件多车型复用。
  • 工作温度、振动、冲击、防护等级满足车规条件；适应晴雨、冰雪、低附着与高低温环境。
  • 供电电压波动、电磁兼容满足车载电气环境；高压部件满足电气间隙、爬电距离与绝缘隔离要求。

9.信息安全与信息管理

  • 控制指令与诊断通信具备身份鉴别、完整性校验与防篡改能力；诊断与 OTA 通道需访问控制与安全刷写。
  • 统一管理运行数据、故障日志、标定参数与软件/标定版本，保证可追溯、可回滚；变更走配置管理并留痕。
  • 运行与故障数据按安全要求存储传输，日志时间戳与车辆配置一一对应，支持复盘与责任界定。

10.法规、保障与约束

  • 法规：满足车辆准入、功能安全（ISO 26262）与预期功能安全（ISO 21448 / SOTIF）及数据安全、远程监管相关要求，证据可追溯。
  • 保障：运营期提供远程监控、在线诊断、保养提醒、备件与维修支持；软件缺陷经 OTA 修复并可回滚；退役时完成部件回收与数据清除。
  • 约束：冗余配置控制在整车成本目标内；需求基线、适配、测试认证与投放节点按计划锁定；受研发算力、台架、场地与供应链产能约束。
  • 假设与依赖：假设上游按约定接口输出有效指令；依赖 BMS 电池约束、定位信息与云端 OTA/监控后台；性能受整车动力、电池与传感器配置约束。
PART 02

初始系统架构（Initial System Architecture）

1.逻辑架构分层

按「决策 — 计算 — 执行 — 反馈」划分逻辑层次，明确各层职责与交互边界。

L1 上游决策层
自动驾驶大脑（感知 / 决策 / 规划）、高精定位、V2X。输出规划轨迹与运动指令，不参与底盘闭环控制。
L2 域控计算层
底盘域控制器 CDC：SoC + 安全 MCU + 网关；运行运动解算、VDC/ESP、轨迹跟踪与状态监控策略。
L3 执行层
SbW 转向 / BBW 制动 / DbW 驱动 / 主动悬架四大执行子系统，按域控指令完成车轮运动调节。
L4 感知反馈层
传感器组：轮速、转角、扭矩、制动压力、IMU、悬架状态等，向域控闭环反馈车辆状态。

2.物理架构组成

物理架构由作业 1 拆解的六大系统构成，子系统与模块划分保持一致：

系统主要子系统 / 模块
线控转向 SbW前/后轴转向执行电机与传动机构、路感反馈子系统、角度/扭矩传感器组。
线控制动 BBWEHB（主缸模拟器 + 轮缸调压阀）、EMB（四轮卡钳电机 + 驻车执行器）、制动冗余单元（蓄能器 + 隔离阀）。
线控驱动 DbW前/后轴电机控制器与扭矩分配、BMS 能量管理与高压配电、制动能量回收。
主动悬架空气弹簧单元、CDC 可变阻尼减振器、悬架控制器。
底盘域控制器计算平台（SoC + 安全 MCU + 网关）、决策算法（VDC / ESP / 轨迹跟踪）。
冗余安全系统双电源冗余、双总线通信冗余、功能安全监控单元（看门狗 / 独立 MCU）。
架构说明：初始架构以「集中式域控 + 分布式执行器」为基线，预留算力与接口扩展空间；详细子系统树见 作业 1 系统树。
